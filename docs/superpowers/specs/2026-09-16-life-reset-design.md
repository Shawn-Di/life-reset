# Life-reset 设计规格

## 1. 目标

构建一个 GitHub 开源、可被多个 AI 工具安装或复制使用的提醒 Skill。第一版只围绕 Dan Koe 的文章《How to fix your entire life in 1 day》，通过自动化在预定时间创建一个新对话，并把该对话初始化为持续启用“Life-reset 导师模式”的会话。

产品显示名为 `Life-reset`，包名为 `life-reset`。由提醒创建的对话标题永远为 `Life-reset`。

## 2. 范围

### 第一版包含

- 一个平台无关的提醒内容格式。
- 一份基于目标文章的中文提醒内容。
- 用户可配置的提醒时间窗口、频率和时区字段。
- 新对话提醒协议：自动化创建新对话，并以提醒消息作为首条消息。
- 新对话默认永久启用 Skill：在该对话生命周期内持续使用人生导师模式。
- 默认主题路由：优先回答个人成长、目标、习惯、行动、复盘和人生方向相关问题。
- 主动提醒默认开启，并支持在对话中通过提示词关闭或重新开启。
- Skill 不拥有独立 Token；调度和对话操作始终使用用户在对应 AI 工具中的账号、权限和 Token。
- 首次提醒创建 `Life-reset` 新对话；后续提醒优先继续同一对话，原对话不存在或不可访问时才创建新的 `Life-reset` 对话。
- Codex 适配说明，以及其他平台的通用适配契约。
- 内容来源链接、作者信息和简短摘要。

### 第一版不包含

- 抓取 X 或 newsletter 的实时内容。
- 收录或重新发布文章全文。
- 账号登录、云端数据库和统一托管服务。
- 依赖平台私有 API 的强制弹窗、阻断或确认机制。
- 多作者、多主题内容推荐界面。

## 3. 核心架构

项目分为三层：

1. **Content Pack**：保存提醒文案、来源链接、主题和行动问题。
2. **Reminder Contract**：规定提醒状态、配置字段和新对话消息格式。
3. **Platform Adapter**：把统一提醒契约映射到目标 AI 工具的 Skill、工作流或自动化能力。

核心层不依赖任何具体平台。平台负责调度提醒、维护用户级提醒开关和上次对话引用，并在已有对话可访问时继续发送，否则创建标题为 `Life-reset` 的新对话。

Skill 不提供账号 Token，也不代替用户登录。每个平台适配器都使用该平台本身授予用户的身份和权限。

## 5. 内容协议

`life-reset.json` 保存以下信息：

- `id`：稳定的内容 ID。
- `title`：提醒标题。
- `author`：作者。
- `sourceUrl`：原文链接。
- `sourcePublishedAt`：原文发布日期。
- `summary`：不超过几段的中文摘要。
- `prompt`：给用户思考的问题。
- `action`：当天可执行的最小行动。
- `copyrightNote`：说明仓库只保存摘要和链接，不保存全文。

提醒文案由这些字段拼接生成，不在各平台适配器中重复维护。会话指令不复制文章全文，只定义 Skill 的持续启用方式和主题优先级。

## 6. 提醒状态与数据流

```text
调度器到达时间
        ↓
读取用户级提醒开关和上次对话引用
        ↓
提醒关闭？──是──→结束本轮
        ↓ 否
加载 life-reset 内容包并生成 reminder message
        ↓
上次对话仍可访问？──是──→继续该对话并发送提醒
        ↓ 否
创建标题为 Life-reset 的新对话
        ↓
注入 life-reset mentor session instruction 和提醒消息
```

首次提醒创建新对话；后续提醒读取上次对话引用，若对话仍存在且可访问，就在原对话中继续发送提醒，不新建对话；若对话已删除或不可访问，才创建新的 `Life-reset` 对话并更新引用。新对话创建后，Skill 在该对话生命周期内默认持续开启。后续回答优先围绕人生导师相关内容展开，包括个人成长、目标设计、习惯、注意力、行动和复盘；用户明确提出其他主题时，正常回答该主题，但不需要关闭 Skill。第一版不要求用户点击“已读”。“提醒消息已发送或新对话已创建”就是提醒成功；如果平台返回失败，适配器记录错误并允许下一次调度重试。

用户可在对话中使用自然语言提示词控制主动提醒，例如“关闭 Life-reset 提醒”“开启 Life-reset 提醒”。适配器应将这类意图写入用户级配置，使后续调度遵循最新状态；默认值为 `enabled: true`。

持续会话指令的语义固定为：

```text
你正在运行 `Life-reset` Skill。
在本对话的整个生命周期内保持人生导师模式。默认优先处理个人成长、人生方向、目标、习惯、注意力、行动和复盘相关内容；回答要具体、诚实、可执行。用户明确提出其他主题时直接回答，不要强行把无关问题解释成成长问题。
```

建议内部状态值：

- `scheduled`：等待调度。
- `skipped`：提醒已关闭，本轮不发送。
- `sent`：提醒已发送到已有对话。
- `created`：新对话已创建并发送提醒。
- `failed`：创建失败，保留错误信息。

## 7. 提醒配置

配置保持平台无关：

- `enabled`：是否启用。
- `timezone`：用户时区。
- `frequency`：例如每周 2 次。
- `timeWindow`：允许创建新对话的时间范围。
- `randomize`：是否在时间窗口内随机选择时间。
- `conversationId`：上一次成功提醒所在对话的平台 ID。
- `conversationTitle`：固定为 `Life-reset`。

具体平台如果不支持随机调度，可以退化为固定时间；如果不支持继续向既有对话发送消息，可以退化为每次创建新的 `Life-reset` 对话；适配器必须在文档中说明限制。

## 8. 平台适配边界

每个平台适配器只包含：

- 安装位置和安装方式。
- 对应的工作流 / 任务配置示例。
- 创建新对话时需要注入的首条消息模板。
- 创建新对话时需要注入的持续会话指令。
- 读取和更新用户级提醒开关及上次对话引用的方式。
- 平台能力限制。

Codex 作为第一适配目标，使用用户自己的 Codex 账号、Skill 指令和自动化新建/继续对话能力。其他平台先提供契约和手动配置模板，不假设其拥有相同的自动化 API。若平台不支持真正的会话级持久指令，则将该指令放入首条消息，并在每次生成新对话时重新注入。

## 9. 错误处理

- 内容文件缺失或格式错误：启动时失败，并指出文件路径和字段。
- 时间配置无法解析：拒绝本次调度，不创建空提醒对话。
- 新对话创建失败：记录 `failed` 状态和平台错误，不重复创建同一轮提醒。
- 用户已关闭提醒：记录本轮跳过，不创建或发送对话消息。
- 上次对话不存在或不可访问：创建新的 `Life-reset` 对话，不把不可访问错误误判为发送成功。
- 平台无法保持会话指令：降级为首条消息中的明确模式声明，不宣称 Skill 在平台内具有系统级永久权限。
- 平台不支持新对话自动化：输出可复制的提醒消息和人工配置方式。
- 网络不可用：第一版不抓取远程内容，已有内容仍可正常生成。

## 10. 测试策略

- JSON Schema 校验内容包和提醒配置。
- 测试提醒消息包含标题、行动、思考问题和来源链接。
- 测试新对话初始化内容包含持续启用 Skill 的会话指令和人生导师主题优先级。
- 测试默认提醒开关为开启，并能解析开启 / 关闭提醒的自然语言指令。
- 测试已有 `conversationId` 可访问时发送到原对话，不创建新对话；对话不存在时创建标题为 `Life-reset` 的新对话。
- 测试缺失字段、非法时间窗口和未知状态会得到明确错误。
- 对 Codex 适配器做一次端到端手动验证：触发自动化，确认生成独立新对话且首条消息为提醒。
- 不测试第三方平台未提供的私有 API 行为。

## 11. 后续扩展

在第一版稳定后再考虑：

- 加入文章中的多个阶段提醒，例如早晨反思、白天打断自动驾驶、晚间总结。
- 增加更多 Dan Koe 个人成长内容，由用户选择启用。
- 增加内容版本和已提醒记录，避免短期重复。
- 为不同平台提供真正可导入的自动化文件。
- 增加用户自己的目标、反愿景和行动记录。
